# Publication checklist

Publication authorization covers a new public repository and open-access distribution. This checklist records concrete work and outstanding operational verification; it does not introduce another approval request.

## Public source candidate

- [x] Target: `MFSCV/seo-geo-system`, newly exported rather than private history.
- [x] Public publication and open access authorized by the project owner.
- [x] MIT license and notices included for original authored code and documentation.
- [x] English onboarding explains current tools, agent specifications, future runtime, and connector limitations.
- [x] Initial maintainer, contribution policy, governance, and reporting guidance documented.
- [x] Final candidate file manifest and hashes generated after all component adaptations.
- [x] Automated private-data/secret checks and manual review completed for the exact candidate.
- [x] Skill auditor and any adapted observer tests pass on the exported tree.
- [x] Catalogs, JSON examples, relative links, and source status checked.
- [ ] Commit created and pushed to the new repository's default branch.
- [ ] Remote commit, public visibility, license detection, and anonymous source access verified.
- [x] GitHub private vulnerability reporting enabled and verified. Branch protection is not configured; no protection or independent-approval guarantee is claimed.

Final verification may be recorded in a separate report to avoid claiming a pass before evidence exists. Preserve that report's commit or manifest reference.

## Future installable or connected releases

These conditions are not claims about the source preview:

- Reproducible installation and supported toolchain documented.
- Dependencies inventoried and pinned/locked as appropriate, with license and vulnerability review.
- Meaningful offline, denial, recovery, budget, and wrong-target tests for every advertised runtime capability.
- Per-operation connector qualification, scoped/revocable credentials, operator authority, and rate/cost/egress controls.
- Untrusted PR execution isolated from release and production privileges.
- Accurate release artifacts, checksums, source revision, and software inventory.
- Migration, rollback, revocation, and actual delivery verification for publishing integrations.

A successful publication grants access to the source under its license. It does not prove search performance or turn specifications into an autonomous service.
