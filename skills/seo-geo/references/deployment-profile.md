# Deployment profile guide

Keep real deployment settings outside the distributed skill. Load the operator's authorized profile for the current task; the synthetic examples in this repository grant no access or publishing authority.

Record the public domain, exact platform/site/property identifiers, environment, source and published revisions, markets, actual page languages, offered products/services, authoritative price source and expiry, content owners, competent reviewers, tracker, existing writer and supported schedules. Resolve these fields from current evidence rather than from an older conversation or a historical plan.

Use a synthetic domain such as `https://example.test/` in examples. Keep credentials, personal data, private evidence, queues and live deployment identifiers out of repository commits, model packets and public reports. Store references to authorized secret storage rather than secrets in a profile.

Specify acquisition pages separately from calendars, checkout, accounts and private surfaces. Define which pages/locales have accepted content and which remain drafts; a language selector does not establish translated content. For regulated subjects, competent humans retain actual factual, clinical, legal and commercial review responsibilities.

Name the existing execution authority, field writers and locks or leases that really govern the target. A public skill cannot create authority by naming a role. Unavailable coordination may permit isolated preparation where the operator's policy allows it, but cannot support a false claim that shared work was integrated.

Define the intended conversion journey. If the goal is direct appointment selection, verify that the CTA reaches date/time selection for the exact service and locale without creating a hold, booking, payment or notification during a crawler or smoke test. Other products should define their own safe stopping point.

The repository's [deployment example](../../../examples/deployment.example.json) is design documentation. Validate it against the public contracts and then adapt it privately; it is not an installed runtime configuration or proof that connectors are operational.
