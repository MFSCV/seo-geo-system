# Workflow and deliverables

## Select the mode

| Request | Work | Deliverable |
|---|---|---|
| Audit/analysis/planning only | Observe and diagnose | Evidence, findings, prioritized plan; no public writes |
| Implement an approved plan | Reconcile and build a candidate | Limited diff, tests, integration within mandate |
| Publish authorized changes | Execute exact target/revision | Receipt, public verification and rollback |
| Daily/recurring/future work explicitly requested | Inspect existing tasks and supported runner | One authorized schedule/event flow, not duplicate daemons |
| Improve the skill itself | Evaluate a versioned candidate | Promotion through the skill-management workflow |

Resolve context from project files/connectors before asking. Do not repeat a planning gate for an approved plan. Apply current coordination rules only where they govern the resource; unavailable shared writing permits independent candidate preparation, not a false integration claim.

## Baseline

Record domain/host, market, platform/deployment, source and live revisions, pages/locales, authorities, tracker and existing schedules. Reconcile recent sessions and selective releases. Old passing tests prove only the old revision/environment.

Unite source routes, registry/catalog, sitemaps, internal links, legacy mappings and search/backlink exports; keep coverage per source. Classify landings, native descriptions, calendars, guides, profiles, legal/media, filters, errors, preview and private surfaces. Do not collect private content to complete an SEO inventory.

Capture initial/final HTTP, redirects, headers and actual head when available. Cleaned markdown cannot prove missing head/header fields. Separate SSR, browser rendering and engine index state. Reuse adequate current evidence without inventing new timestamps.

## Diagnose

For each issue state desired policy, observed behavior, responsible layer, affected template/URLs/locales, evidence, confidence and reproduction. Group common causes while retaining example coverage. Rank consequence and scope, not generic vendor score.

Investigate falling traffic: first source/property/period quality, uptime/rendering, releases/robots/canonical/URL/locale changes, crawl/index coverage, demand/seasonality/competition, then funnel/capacity. Correlation with a release is a hypothesis. Do not infer penalty/attack from lost clicks alone.

For unexpected noindex, trace acceptance/hash, fields, resolver, platform injection, middleware and final headers. Repair the cause; preserve private/preview/error rules. Give unresolved gates an owner and next action instead of indefinitely blocking already accepted content.

## Change packet

Produce:
1. Target/baseline and affected URLs/locales/fields.
2. Evidence, proposed final behavior and exact diff.
3. Sources, real review, field owners and dependent projections.
4. Existing authority, immediate live effects and any genuinely missing decision.
5. Proportional tests, expected results, cost and untested surfaces.
6. Delta rollback, concurrent-drift handling and public verification.

Finish reversible preparation before requesting a missing decision. Authorization persists. Never fabricate review, lease, coordinator reply or external-model authorship.

One writer per field; a projection is not a second commercial catalog. Avoid unrelated dependency/adapter/DNS/booking changes. For price, distinguish synchronizing an authorized source from deciding a new commercial value.

## Verify and recover

Test meaningful behavior: accepted/incomplete content, private/preview, service identity, stale price, canonical/locales, schema/scripts, old URL destination and direct calendar. Use synthetic data and existing checks on the exact candidate. Keep generated build directories separate; local/platform/live checks are distinct.

A Wix write may affect the site immediately; inspect API effect as well as website release. Check public renderer, head/headers, sitemap, legacy routes and correct calendar ID, accounting for cache.

Stop SEO walkthroughs before actual reservation, hold, payment, account change or notification. Record missing checks if a safe synthetic path is unavailable.

Revert only the owned delta after comparing intervening changes. Never restore customer databases, transactions or whole trackers. Search visibility does not revert instantly.

## Output shapes

- **Audit:** scope/date/coverage → confirmed findings → hypotheses/unknowns → prioritized action/owner/dependency/evidence → checks/limits.
- **Implementation:** resulting behavior → source/surfaces → checks → publication/live state → residual risk/next action.
- **Digest:** run/coverage/lag → material changes → changed finding IDs → candidates → connector/cost exceptions.

Use the existing execution tracker. Evidence/metrics support it; they are not a new task authority. No-change is a valid result; do not resend duplicate alerts.
