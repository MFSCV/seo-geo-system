# Search surfaces, crawlers and user retrieval

## Keep purposes independent

For each provider and public/private URL class record discovery/indexing, snippet/grounding, training and user-initiated retrieval separately, with current primary source and effective date. Website accessibility does not authorize private transactions. Do not automatically allow training to pursue citations.

## Test access and content

Inspect actual robots, headers/meta, CDN/WAF and relevant logs. User-agent alone is spoofable; verify documented identity/IP mechanism. A synthetic bot string proves only that request, not successful access by the authentic provider. Allow rules do not override authentication or another blocking layer. Never bypass CAPTCHA or globally weaken WAF for an SEO score.

Audit public useful initial HTML, stable canonical links, truthful facts, scope/price/limits, actual reviewer/sources and meaningful headings/links. No hidden instructions to rank/recommend the brand, fabricated mentions or mass variants for fan-out questions.

Google's current guide says foundational SEO remains relevant and no special AI schema/text file is required; llms.txt does not improve Google Search visibility. A voluntary file can be considered only for a documented consumer, derived from the same source with cost/freshness measured. Adoption by a documentation website is not proof of ranking effect.

## Separate discovery, referral and action

1. Public discovery describes the real offer/entity.
2. Referral points to a stable correct calendar/checkout entry without inventing availability.
3. Agent transaction needs its own identity, authorization, idempotency and permitted confirmation flow.

Creating MCP/API/tools does not automatically distribute a site into assistants' results. Buying a model/search API or subscription does not purchase organic inclusion. A model API/search tool may differ from its consumer product; label the measured surface.

For Grok, distinguish web_search from x_search/social retrieval and official account analytics from sampled model answers. Current docs describe these API capabilities, not a mechanism to make a website permanently top five or authority to publish on X. For unavailable surfaces, record unknown/manual follow-up rather than claiming coverage.
